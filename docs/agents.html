Agents

Sinclair doesn't launch or orchestrate agents for you — you run Claude Code, Codex, or any other agent CLI in a pane, the same way you'd run any command. What Sinclair adds is the supervision around them: a status dot per pane, an MCP server agents can drive the terminal through, one container to hold the project and its agents, a worktree per agent, and resumed sessions after a restart.

Run an agent

Open a tab or split and start the CLI: claude, codex, or anything else. To run several side by side, open a tile from the Workspace menu — built-in presets (Two/Three Columns, Two Rows, Grid, Main + Bottom Row, Main + Right Stack) open that arrangement of shells in a new tab, and Save Current Layout… captures the focused tab's split structure as a named layout (stored as JSON under ~/.config/sinclair/layouts/). See Tabs, splits & layouts.

Agent status

Every pane has a semantic state — working, blocked (waiting on you), done, or idle — that shows up as a colored dot on its tab and is rolled up in the Activity panel. It's the fastest way to read a window full of agents at a glance: who's heads-down, who's blocked, who's finished.

Claude Code reports these states through its lifecycle hooks. Run sinclair agent-hooks install once and its dot tracks its work automatically; anything else can report with sinclair agent-status. See the Agent status at a glance tutorial.

The MCP server

sinclair mcp exposes the running terminal to any MCP client, so an agent can read the screen, send input, open tabs and splits, replay macros, manage worktrees, check other panes' states, and post notifications. Turn it on with MCP server under Settings → Agents (mcp-server-enabled). Full tool list: MCP server.

The shared sandbox

An agent working in your checkout is working on your real machine, with your real credentials. Turning on File ▸ Sandbox ▸ Use Sandbox for This Project puts the project and every agent you run in it inside one container instead: one filesystem, one toolchain, one blast radius. It needs Docker or Podman and nothing else, and its settings live under Settings → Agents. Full walkthrough: Share one container with your agents.

A worktree per agent

Create, open, and remove git worktrees from keybinds or MCP verbs, each opening a tab at the checkout — one isolated branch per agent, with triggers for setup and teardown. See Parallel agents in git worktrees.

Resume, don't restart

With session-restore on, a pane that was running claude or codex is remembered as one, along with the native session id its hooks reported. On restore it relaunches resumed — claude --resume <id> or codex resume <id> — instead of dropping to a bare shell. Other commands relaunch unchanged; plain shells restore exactly as before. Whether the conversation comes back intact is up to the agent CLI: Sinclair threads the session id, the provider reloads its transcript.
